# 架构说明

```text
用户输入
   │
   ▼
01 原始数据记录 ───────┐
   │ 正式提交 + D分析   │
   ▼                    │
H1 健康层（非阻塞）      │
   │ 客观日汇总/报告      │
   └──────────────┐     │
                  ▼     ▼
              02 数据筛查
                  │ 正式 Decision
                  ▼
              03 状态快照
```

## 边界

- `01` 保存用户原始事实和确认结果，不自动补写主观字段。
- `H1` 只处理导入的客观健康信号；健康缺失不阻塞主链，也不推断情绪或动机。
- `02` 只接收已确认的 01 正式输入和来源链，生成可追溯的决策对象与派生账本。
- `03` 一次只处理一个正式 Decision；状态快照不能授予严格回测或因果结论资格。
- `personal-system-orchestrator` 负责跨层路由、日期门禁、停止条件和交接回执。

## 可恢复性

每个正式产物应携带路径、SHA-256、版本和登记状态。来源变化、同日冲突、缺失用户确认或结构不一致时，保留已通过阶段并停止继续推进。

## 公开发布边界

公开版本建议只包含规则、Schema、Skill、测试夹具、示例和文档。真实 Vault、健康数据库、导出包、日记、日报、历史归档和恢复包应留在仓库外。
