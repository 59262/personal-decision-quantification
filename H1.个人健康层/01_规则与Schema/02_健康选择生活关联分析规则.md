# 健康、选择与生活关联分析规则 v1.0.0

## 1. 目标与适用范围

本规则用于今后的日、周、月分析，回答三类问题：某段健康状态是否早于后续生活或选择节点；某项生活或选择是否早于后续健康变化；两类现象是否只是同日或同期共现。

它使用现有Apple健康记录、正式日报、D分析及用户明确纠正，不增加每日必填字段。单日材料只能产生事实、时间关系和待验证候选，系统不得自动输出因果结论、疾病判断、人格结论或主观状态推断。

## 2. 分析对象

### 2.1 健康侧

- 睡眠、心率、HRV、血氧、步数、活动能量、训练、体重及其他有来源的设备事实；
- 用户明确确认的身体或健康事实；
- 带算法版本、数据窗口和覆盖说明的派生指标；
- 缺失、佩戴不足、设备或算法变化等质量信息。

### 2.2 选择与生活侧

- 正式Decision及其选择点；
- 任务计划与实际边界；
- 工作、通勤、饮食、训练、休息、娱乐和睡眠等生活事件；
- 可观察的活动切换；
- 用户明确说出的理由或解释。

没有正式Decision的日期仍执行本规则。反思和未来计划可以作为用户表达记录，但不自动当作已发生的选择或行为。

## 3. 时间方向

所有候选关系先放入统一时间轴。对任一生活或选择节点`t`：

1. 只有结束时间不晚于`t`的健康窗口，才可作为前置客观情境；
2. 开始于`t`之后或跨过`t`的健康窗口，只能作为同期或后续结果；
3. 日期D的主要睡眠按`D日18:00至D+1日12:00`归入D日晚间结果，不能解释D日白天的选择；
4. D-1日晚开始、在D日事件前结束的睡眠，可以作为D日的前置恢复情境；
5. 事件时间缺失时，只能写“同日共现”，不能判断先后方向；
6. 日记时间与设备时间冲突时保留两者并降为`unknown`或`co_occurrence`。

关系方向只允许：

| direction | 含义 |
|---|---|
| `health_before_life_or_choice` | 健康窗口结束后才发生生活或选择节点 |
| `life_or_choice_before_health` | 生活或选择节点后才出现健康窗口或指标 |
| `overlap_or_co_occurrence` | 时间重叠或只有同日信息，方向不明 |
| `user_stated_explanation` | 用户明确说出的解释，只证明其表达 |

## 4. 证据等级

| 等级 | 最低条件 | 允许表述 |
|---|---|---|
| `unknown` | 来源、覆盖或时间不足 | 当前无法判断 |
| `single_day_temporal` | 单日内方向可排序，且两端来源可追溯 | 当日先后关系／时间关联 |
| `cross_source_aligned` | 日记与设备独立记录在时间和事件上对齐 | 两个来源一致支持该观察 |
| `repeated_candidate` | 至少3次可比观测同方向出现，并保留反例 | 重复候选，仍非稳定规律 |
| `baseline_supported_candidate` | 至少14个有效健康日、配对样本足够，效应方向与个人初始范围一致 | 初始基线支持的候选关联 |
| `rolling_supported_candidate` | 至少28个有效日，滚动窗口与敏感性检查后方向仍稳定 | 滚动数据支持的个人候选规律 |

等级只表示证据强度，不表示因果。用户明确解释单独标为`user_stated_explanation`，不得代替统计支持。

## 5. 每日算法

```text
A0 读取来源、哈希、版本、覆盖和时间质量
→ A1 分别提取健康事实与生活／选择节点
→ A2 统一时区和时间窗口；保留开始、结束与精度
→ A3 对每个节点建立前置、重叠和后续窗口
→ A4 生成候选配对，先判方向，再判来源一致性
→ A5 检查反例、替代解释、日类型和设备覆盖
→ A6 赋证据等级；缺失不插值，主观字段不推断
→ A7 输出最多3条当日最有信息量的关联及未知边界
→ A8 将可比较候选交给W/M累计，不在单日升级为稳定规律
```

候选优先级依次为：精确时间对齐、跨来源一致、与正式选择点或明确生活节点有关、存在可验证后续窗口。只因数值极端但无法连接生活节点的项目留在健康摘要，不强行制造关联。

## 6. 多日算法

### 6.1 样本门槛

- 少于14个有效健康日：只累计观察和重复次数；不宣布个人范围或稳定模式。
- 14至27个有效日：可使用中位数与MAD建立初始个人范围，输出`baseline_supported_candidate`。
- 至少28个有效日：使用滚动个人基线，并检查最近窗口与全窗口方向是否一致。

“有效日”要求目标指标有足够覆盖、来源和算法口径一致。设备更换、佩戴习惯或算法变化建立阶段边界，不直接拼接。

### 6.2 比较方法

- 连续指标对连续结果：优先Spearman秩相关；配对样本不少于14时才报告自助法置信区间。
- 类别／是否事件对连续结果：报告两组中位数差与Cliff's delta；每组至少5个有效观测且总数不少于14。
- 同时筛查多组关系：达到28个有效日后使用BH方法控制假发现率；此前只按证据完整度排序，不使用“显著”表述。
- 无论数值结果如何，都同时报告样本数、缺失率、覆盖窗口、方向、反例和可能混杂。

### 6.3 必查混杂与敏感性

至少检查日类型、计划训练或休息、设备覆盖、疾病或症状、工作日／休息日、重大作息变化。样本允许时分别比较：去除低覆盖日、只保留精确时间事件、按日类型分层。方向改变时必须降级。

## 7. 缺失、反证与表达边界

- 主观精力、压力、情绪、困倦、疼痛、动机和阻力缺失时保持未知；健康数据不得代填。
- 设备缺失不写0，用户未提及也不写“没有发生”。
- 事件无时间时不用于方向性统计，只进入同日共现计数。
- 每条候选必须保留至少一个反例、替代解释或明确写“当前无可用反例”。
- 使用“相关、同期、先于、随后、候选关系”；除非另有实验设计和授权，不使用“导致、改善、恶化、决定”。

## 8. 固定输出

今后的D报告在健康摘要之后固定增加：

```markdown
### 6.1 健康、选择与生活关联
| 关联对象 | 前置证据窗口 | 生活／选择节点 | 后续结果窗口 | 方向 | 证据等级 | 当前可说 | 未知／反证 |
|---|---|---|---|---|---|---|---|

- 当日最强关联：最多3条；不足则按实际数量。
- 多日候选状态：无／累计中／repeated_candidate／baseline_supported_candidate／rolling_supported_candidate。
- 未知边界：时间、覆盖、样本或混杂。
```

健康资料缺失时本节仍保留，写`pending_health_data`。本节提出的模型解释计入D报告“最多2条可检验假设”总上限。

W层聚合重复次数、反例、分层结果和证据等级变化；M层只汇总跨周仍存在的候选、降级原因和下阶段验证条件。历史报告不因本规则发布而回写。
