# 苹果健康与视频日记联合分析协议 v0.2

## 1. 目的

本协议用于把苹果健康客观数据与同日视频日记放在同一时间轴上，生成可追溯、可重复、可逐日比较的个人健康研究报告。

报告只描述个人观察、时间关系和待验证假设，不进行疾病诊断，也不依据心率、HRV、睡眠或活动数据推断情绪。

## 2. 输入

每次分析至少读取：

1. 苹果健康原始样本和导入批次；
2. 当日健康汇总；
3. 视频日记原文；
4. 经用户确认的正式日报；
5. 用户在分析前提供的纠正；
6. 已有个人基线，达到有效样本要求后才使用。

## 3. 证据分类

| 标签 | 含义 | 示例 |
|---|---|---|
| `device_fact` | 设备或健康应用实际保存的样本 | 步数、心率、训练起止时间 |
| `user_fact` | 用户明确陈述并确认的事实 | 完成40分钟有氧、正式体重 |
| `derived_metric` | 由程序从样本计算的结果 | 睡眠总时长、区间平均心率 |
| `temporal_association` | 两件事在时间上邻近或同时出现 | 训练结束后出现关于确定性的反思 |
| `research_hypothesis` | 需要未来样本验证的解释 | 运动可能提供可见成长和确定感 |
| `unknown` | 当前材料不足 | 焦虑时刻的独立静息心率反应 |

设备事实、用户事实和派生结果可以同时存在。来源冲突时不删除旧值，在报告中记录采用口径和冲突值。

## 4. 日期与睡眠归属

### 4.1 日间数据

活动、心率、训练、体重、饮食和日记事件按自然日00:00—24:00归属。

### 4.2 夜间睡眠

报告日期的主要睡眠窗口定义为：

```text
报告日期18:00 → 次日12:00
```

只要主要睡眠从报告日期晚间开始，整段睡眠归入该日期的“当晚睡眠与次晨恢复”。午睡以后单独建模，不混入主要夜间睡眠。

睡眠属于当天之后的恢复结果。它可以用于观察次日状态，不能作为当天白天事件的前置原因。

## 5. 冲突处理

1. 用户明确纠正自身行为事实时，以最新确认作为正式口径；旧值保留在冲突记录中。
2. 设备测量值与用户记录不同，两者都保存；报告明确哪一个作为正式展示值。
3. 设备未记录不等于行为没有发生。用户确认完成的活动保存为`user_fact`。
4. 用户没有陈述情绪时，生理数据不能补写情绪。
5. 时间重叠不自动代表因果关系。

## 6. 联合分析流程

```text
G0 输入与来源审计
→ G1 单位、时区、日期和睡眠归属修正
→ G2 用户纠正与来源冲突登记
→ G3 设备事实和日记事实分别提取
→ G4 按真实时钟建立联合时间线
→ G5 运动、恢复、心血管、身体和行为分域分析
→ G6 对健康、选择与生活节点先判断时间方向
→ G7 按单日、跨来源、重复、14日初始范围和28日滚动基线分级
→ G8 登记研究假设、反证条件和后续观察字段
→ G9 输出Markdown与JSON报告
```

## 7. 每日报告结构

1. 输入审计与正式纠正；
2. 当日健康概览；
3. 联合时间线；
4. 活动与训练；
5. 心率与心血管信号；
6. 睡眠与恢复；
7. 身体和其他健康指标；
8. 日记中的主观状态；
9. 跨域观察；
10. 研究假设与未来验证；
11. 数据质量和限制。
12. 健康、选择与生活关联矩阵。

## 7.1 关联矩阵

关联分析执行`E:/个人事件量化系统/H1.个人健康层/01_规则与Schema/02_健康选择生活关联分析规则.md`。每条记录至少包含健康窗口、生活／选择节点、后续窗口、方向、证据等级、当前可说、反证或未知以及来源哈希。

- 只有结束时间不晚于节点的健康窗口可作前置情境；
- D日晚间至D+1次晨的睡眠是D日后续结果，不能解释D日白天节点；
- 没有正式Decision时仍分析任务、活动切换、饮食、训练、休息、通勤和工作节点；
- 事件无时间时只能写同日共现；
- 单日不得输出稳定规律或因果。

## 8. 基线与异常门槛

- 少于14个同源有效日：只做单日观察；
- 达到14个有效日：建立初始个人范围；
- 达到28个有效日：启用滚动个人基线；
- 设备更换、佩戴习惯变化或算法升级时建立阶段边界；
- 异常提示必须包含基线窗口、样本量、数据覆盖和可能的活动解释。

## 9. 心率分析规则

1. 训练和通勤窗口内的心率首先按身体活动解释；
2. 只有在相对静止、数据覆盖充分且时间可对齐时，才描述与主观事件同时出现的心率变化；
3. 日均心率是按设备采样点计算的样本均值，不能直接代表全天时间加权平均；
4. HRV、静息心率和血氧在个人基线形成前只展示数值；
5. 单日数值不用于判断稳定健康状态。

## 10. 能量与饮食规则

日记中的餐食热量通常是本人估算，设备能量通常也是模型估计。除非摄入完整、测量口径稳定且覆盖全天，否则不计算或宣称真实能量缺口。

## 11. 输出状态

| 状态 | 含义 |
|---|---|
| `observation_only` | 数据可读，但没有足够个人基线 |
| `baseline_ready` | 指标达到初始基线要求 |
| `limited` | 来源冲突、覆盖不足或时间无法对齐 |
| `recomputed` | 单位、算法或来源修订后重新生成 |

## 12. 当前适用范围

本协议从2026年10月12日开始试运行。首份报告用于验证结构和数据边界，不作为个人健康常态或异常基线。

v0.2.0从2026年10月15日起用于新生成或明确重建的联合报告。2026年10月12日至14日既有报告保留v0.1.0，不自动回写。
