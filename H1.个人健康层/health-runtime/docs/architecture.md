# 健康层 v0.1 技术架构

## 决策摘要

首版采用 Python 标准库与 SQLite，原因是 Windows 可直接运行、无需云服务、无需安装数据库服务器，并且便于对每一次导入和重算进行审计。核心数据模型不绑定未来界面；后续可以在相同数据库契约上增加本地 Web UI 或 iPhone HealthKit 采集器。

## 数据流

```text
Apple 健康 export.zip / export.xml
  → 文件哈希与导入批次
  → 流式 XML 解析
  → health_raw_samples（不可覆盖、确定性 sample_id）
  → health_normalized_samples（指标与单位映射、带版本）
  → health_daily_summaries（JSON、带计算版本）
  → health_daily_reports（JSON + Markdown）
```

## 分层边界

1. 原始层：保存来源字段、原始属性、元数据、来源文件哈希和首次导入批次。重复导入不会覆盖原样本。
2. 标准化层：保存规范指标名、单位、质量状态和标准化规则版本。未知指标仍保留，并标记为 `unmapped`；指标字典升级后可以不改原始数据直接重建本层。
3. 派生层：按日期生成每日汇总。派生对象可以重算，不修改原始层。
4. 报告层：同一汇总同时输出机器可读 JSON 和用户可读 Markdown。
5. 联合分析层：依据版本化协议将健康数据与视频日记按真实时间对齐，分别保存设备事实、用户事实、派生指标、时间关联和研究假设。

## 当前安全边界

- 默认只监听和写入本机文件系统；当前版本没有任何网络上传逻辑。
- `data/`、`inbox/`、`reports/`、Apple 导出文件和 SQLite 文件均被 Git 忽略。
- 测试数据完全合成。
- 报告不输出疾病名称，不从生理信号推断情绪。

## 已知限制

- Apple 健康可能同时包含 Apple Watch、iPhone 和第三方应用的重叠活动样本。步数和步行距离当前按分钟选择来源：Watch 优先，iPhone 只补足没有 Watch 样本的分钟；`ActivitySummary` 优先于同日活动能量明细。规则仍需要与健康 App 显示值交叉核验。
- 佩戴时长尚未计算，所以覆盖状态是初始判断。
- 基线、异常、周月报和日记连接还未启用。
- 主要夜间睡眠已按“报告日期18:00至次日12:00”归属；午睡识别和多来源睡眠消重仍待实现。

## 下一增量

2. 来源优先级与活动重叠区间处理；

4. 异常证据对象与规则版本；
5. 周报、月报与视频日报链接适配器；
6. 本地可视化界面。
