# 目录、版本与迁移治理

#数据筛查 #版本治理

## 单一权威目录

运行中的数据筛查模块只允许位于 02.数据筛查。00.结构介绍只保留架构说明，不再存放运行数据副本。

## 版本规则

- 当前规则放在工作目录，旧规则移入 99_系统演化档案；
- 同一功能只能有一个明确标注的当前版本；
- 候选版本必须标明 candidate，不得与 active 混用；
- 派生数据应可重建，原始数据与人工审计记录应不可静默覆盖；
- 每次结构或 Schema 变化都要记录原因、映射、影响和验证结果。

## 标准迁移步骤

1. 生成迁移前 SHA-256 文件清单；
2. 明确旧路径到新路径的映射；
3. 移动文件并保留历史原文；
4. 更新当前构建器、Skill、入口和代码本；
5. 重建派生账本；
6. 验证 JSON、JSONL、ID 唯一性、源路径和数量；
7. 生成迁移后清单与演化记录。

## 发布检查

- [ ] 最终日报数量与哈希符合预期
- [ ] 所有 JSON 可解析
- [ ] 所有 JSONL 逐行可解析
- [ ] ingestion_registry 的日期和ID唯一
- [ ] built 登记的最终日报哈希、manifest输入和 build_batch_id 一致
- [ ] 不存在未说明的 source_changed 或 blocked 状态
- [ ] 派生对象 ID 无重复
- [ ] 当前源路径可解析
- [ ] 旧路径存在机器可读迁移映射
- [ ] Obsidian 双链只指向真实文件
- [ ] 演化档案已更新
