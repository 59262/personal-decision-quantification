# 增量接入登记规范

#数据筛查 #增量接入 #Schema

## 1. 目的与边界

`ingestion_registry`是`01.原始数据记录 → 02.数据筛查`的接入控制面，用来回答：某日原始文件是否已被发现、处理到哪一步、对应哪份最终日报、进入了哪个构建批次。

它不保存日报正文，不替代原始提交、筛选工作区、最终日报或派生账本。登记表是可由当前文件状态重新计算的控制快照；历史规则和重大变更写入[[02.数据筛查/99_系统演化档案/00_档案入口|系统演化档案]]。

## 2. 权威文件

- 登记表：`05_质量审计/ingestion_registry.jsonl`
- 同步程序：`06_程序与Skill/构建器/sync_ingestion_registry.ps1`
- 构建清单：`04_派生账本/manifest.json`
- 增量起始日期：`2026-08-17`
- 唯一键：`event_date`
- 稳定ID：`ING-YYYYMMDD`

只有严格匹配`日期：YYYY年M月D日.md`的正式日提交进入自动扫描。临时副本、桌面文件和日记原文不自动登记。

## 3. 最小数据契约

| 字段 | 含义 |
|---|---|
| `source_submission` / `source_sha256` | 01正式日提交的库内相对路径及SHA-256 |
| `analysis_report` / `analysis_sha256` | 同日AI日分析路径及SHA-256 |
| `screening_workspace` | 02日期级筛选工作区 |
| `processing_status` / `status_reason` | 当前机器可判定状态及依据 |
| `final_report` / `final_report_sha256` | 唯一最终日报及SHA-256 |
| `build_batch_id` / `builder_version` | 最终日报最后一次成功进入的派生构建批次 |
| `last_built_*_sha256` | 最近一次成功构建时的上游和最终报告基线 |
| `registered_at` / `updated_at` | 首次发现及最后实质变化时间 |
| `next_action` | 该状态允许的下一步 |

路径统一使用知识库根目录相对路径和`/`分隔符。哈希统一为小写SHA-256。

## 4. 状态机

| 状态 | 判定 | 下一步 |
|---|---|---|
| `waiting_for_analysis` | 有正式提交，无同日日分析 | 完成01日分析 |
| `ready_for_screening` | 提交和分析齐全，无筛选工作区或最终日报 | 进入第二流程 |
| `screening_in_progress` | 工作区存在，最终日报不存在 | 完成质检和事实闭环 |
| `finalized_pending_build` | 最终日报存在，但当前manifest未包含相同哈希 | 运行派生构建器 |
| `built` | 最终日报哈希与manifest输入一致，批次已登记 | 等待新数据或复核 |
| `source_changed` | 最近成功构建后，提交或分析哈希改变 | 停止复用，重新筛选并构建 |
| `source_chain_mismatch` | Manifest最终日报存在，但原始提交或分析哈希不一致 | 核对provenance，重新筛选或构建 |
| `blocked_duplicate_source` | 同一事件日期出现多个正式提交 | 人工确认唯一来源 |

正常单向转换为：

```text
waiting_for_analysis
  → ready_for_screening
  → screening_in_progress
  → finalized_pending_build
  → built
```

任何已构建记录发生上游哈希漂移时转为`source_changed`，不得因为文件名和日期相同而静默沿用旧结果。

## 5. 自动更新点

1. 每次执行日级筛选前先同步，选择最早的`ready_for_screening`日期；
2. 写出最终日报后再次同步，必须得到`finalized_pending_build`；
3. 派生构建器写出manifest后自动同步，必须得到`built`；
4. 同步重复运行且文件无实质变化时，不修改`updated_at`；
5. 登记不能替代流程执行。本版本自动发现和记账，但仍由用户或上层任务触发筛选流程。

## 6. 发布与审计条件

- `ingestion_registry.jsonl`每行必须可解析；
- `event_date`和`ingestion_id`不得重复；
- `built`记录的最终日报、原始提交和分析来源哈希必须与manifest同一输入行一致；
- `build_batch_id`必须与当前成功构建批次一致；
- 所有登记路径必须留在系统根目录内；
- 任何`source_changed`或`blocked_*`状态都必须在交付时显式报告。
