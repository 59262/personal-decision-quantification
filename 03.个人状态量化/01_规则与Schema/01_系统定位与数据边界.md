#03个人状态量化 #系统规则

# 系统定位与数据边界

## 1. 唯一职责

03把一个明确选择点在`information_cutoff`以前的状态保存为`state_snapshot`。状态只回答“当时已知什么、哪些选项可得、用户如何报告自身状态”，不回答最终选了什么、为什么必然如此或哪个选择更好。

## 2. 允许进入的证据

| 来源 | 用法 |
|---|---|
| `pre_lock_user_report` | 实时快照事实的最高优先级 |
| `raw_fact` | 仅当能证明发生在截止点前 |
| `user_recall` | 事后重建可用，必须标记回忆时间和字段 |
| `post_analysis_supplement` | 只能补事实，不得伪造成锁定前记录 |
| `health_objective_context` | H1中截止点前、带路径／哈希／算法版本的客观健康数据 |
| `model_hypothesis` | 不得写入快照事实字段 |

来源冲突或时间边界无法证明时使用`unknown`，不进行无依据填补。

## 3. 状态字段边界

- 精力、压力、困倦、疼痛、情绪、动机和启动阻力优先由用户在对应时点填写。
- AI可以整理用户原话、地点、固定安排、资源和明确限制，但不能从结果倒推状态。
- H1客观数据可以记录截止点前已发生的活动、训练或设备测量；不能代填精力、压力、困倦、疼痛、情绪、动机或启动阻力。
- “应该、想要、冲动、担心”必须保留为用户自述，不转写成人格或因果结论。
- 每个选项分别记录`available_now`、第一动作、启动阻力、预计时长和资源／阻碍。
- 选项必须针对同一决策问题和观察窗口；顺序可同时发生的活动不能假装成互斥选项。

## 4. 严禁混入

- `actual_choice`、`immediate_outcome`、事后结果时长和事后反思；
- 根据实际结果补造的第一动作、预计时长、精力、压力或阻力；
- AI对“真实动机”、人格、诊断或因果关系的判断；
- 04层的预测概率、模型输出和评分结果。
- 结束时间晚于`information_cutoff`的睡眠、活动、心率或其他健康数据。

## 5. 文件生命周期

`draft → user_confirmed → validated → registered → archived/superseded`。只有`registered`的正式快照可供后续阶段读取；正式文件修订必须生成新版本或修订记录，不静默覆盖。
